Skill：Agent 接单赚钱（过三道门槛 + 卖工具）

来源：04《Agent 接单赚钱教程》+ The Penniless Agent 实验、dev.to 13 个真赚钱案例审计。案例数字均为原作者自述、未独立验证，看模式，不要抄数字。

直接把下面的提示词丢给你的 Agent，即可使用这个 Skill。先过检查表，再看两个完整示例，最后按失败回退模板写验收标准。

什么时候用这个 Skill

想让 Agent 赚钱、或判断一个“Agent 自己赚钱”的想法靠不靠谱时用。目标：10 分钟出结论，不踩“7 天 $0”的坑。

核心原则

  • 赚钱的从来不是“无人值守”，是“有人负责”。
  • “零人工不是约束，是 bug。”
  • 卖工具，不卖教程。判定标准：用户付完钱能不能直接用上。PDF/文档类也按这个标准判——能直接用的算工具型交付物，只讲道理的算教程。

一、检查表（可打印，全部打勾才上线）

7 项全部打勾，才上线。有一项打不上，先补那一项。

□检查项怎么判
☐买家是谁？为什么付钱？付多少？能写出具体的一句“谁付钱、为什么付、付多少”，不是“大家都需要”
☐身份谁解决？注册、实名、收款、签合同，每个环节都写清“谁的身份、谁来提供、怎么提供”
☐关键节点谁点头？收款、发布、对外提交、退款等审批清单已列，每天留 5–15 分钟审批
☐交付物是能用的工具？能写出一句“用户拿到的是 ___（能跑的脚本 / 能用的页面 / 能省时间的工具），不是 ___（报告）”
☐卖的是工具，不是教程？用户付完钱能立刻用上，不用你解释；若“还得看教程”，教程已做进工具里

☐失败回退已定？哪个环节失败、整体怎么回退、谁兜底，已写在下面模板里

二、完整示例 1：能上（卖工具，有人负责）

生意：微信聊天记录整理成待办清单的小工具，卖给 3–10 人的小团队，29 元/月

决策：能上。理由：买家具体（小团队负责人，聊天记录太多、待办总漏）；付费原因具体（每天省 20 分钟整理时间）；价格具体（29 元/月）。

三道门（填好的）：

  • 身份：注册用买家自己的手机号 + 微信扫码登录，身份是买家的，不用我们提供；收款用买家自己的微信支付商户号 / 我们的收款码代收（已签代收协议），签合同用买家公司主体，合同模板已备好。
  • 真人点头：审批清单 = 对外发布新版本、退款、导出数据给第三方。每天上午 10 点花 10 分钟审批：发布前看一遍更新说明，退款 100 元以上需负责人二次确认。Agent 只负责整理初稿，不直接对外发布。
  • 交付物：用户拿到的是一个能跑的网页工具——粘贴聊天记录，点一下，出待办清单，可导出、可用。不是一份“聊天记录整理报告”。

卖工具的判定：用户付完 29 元，打开页面就能用，不用看教程。教程（3 分钟上手视频）做进了工具首页的新手引导里，是工具的一部分。

真人反馈闭环：每一条 Agent 整理的待办，负责人点“对 / 错 + 错在哪”（如“这条不是待办，是闲聊”）。每周把“错”的原因汇总一次，反馈给 Agent 调提示词。目标：第一周整理准确率 60%，第四周到 85%——像 Sage / Nova 的批准率从 30% 涨到 70–80% 那样，越带越准。

失败回退：Agent 整理错误率连续 3 天高于 40%，回退为“Agent 只做高亮候选，待办由负责人手动勾选”；微信接口被封，工具切换为“粘贴文本”模式，不阻塞交付；退款请求 24 小时内响应。

成本账：工具运行成本约每月几十元（API + 服务器），1 个付费团队即覆盖；10 个团队即月入 290 元起，边际成本趋近于零——走的是 Rashid 那条“低成本 + 真需求”的路，不是堆量。

三、完整示例 2：不能上（放 Agent 出去自己赚钱）

想法：放一个 Agent 出去，让它自己想办法赚钱，0 启动资金、0 账号

决策：不能上。这就是 The Penniless Agent 实验的翻版，7 天收入 $0。按三道门逐项判：

  • 身份：✗ 无解。注册要手机号、收款要实名、签合同要身份证，Agent 没有身份证。实验里约 25 条赚钱路径，一大半死在这儿。没有“谁的身份、谁来提供”的答案。
  • 真人点头：✗ 无主体。“零人工”是这个想法的卖点，但关键节点（收款、发布、对外提交）没有真人拍板。所有赚钱的案例里，都有真人每天花 5 到 15 分钟点批准；把人拿掉，等于把责任也拿掉了。
  • 交付物：✗ 是报告，不是结果。实验产出 47 个点子、9 份报告，买家问一句“然后呢”就哑火。没有“用户拿到的是什么”的答案。
  • 买家：✗ 没有。“Agent 自己找买家”——Agent 找的是“点子”，不是“买家”。实验里 Agent 招聘板上 95% 是广告，总成交额约 $243，连买家池都没有。

改法（不是直接放弃）：把“放 Agent 出去”改成“你先接一单，再让 Agent 干”——你去找一个具体买家（如上例的小团队），签好合同、定好交付物（能跑的工具），Agent 只负责干活，你负责点头。身份、审批、交付物三道门一过，这个想法就能从“不能上”变成“能上”。

四、失败回退模板（复制后填空）


生意：[一句话：卖什么给谁，多少钱]
买家：[谁付钱、为什么付、付多少]

身份：
- 注册：[谁的身份、谁来提供]
- 实名：[谁的身份、谁来提供]
- 收款：[谁的收款账号、怎么结算]
- 签合同：[谁的主体、合同模板有无]

真人点头（审批清单）：
- [收款 / 发布 / 对外提交 / 退款 / 其他]：[谁审批、每天花几分钟、什么标准通过]

交付物：
- 用户拿到的是 ___（能跑的脚本 / 能用的页面 / 能省时间的工具），不是 ___（报告）
- 用户付完钱，第一步做什么：[具体动作，不用你解释就能完成]

真人反馈：
- 批准/拒绝原因记在哪里：[表格 / 文档 / 工具内]
- 反馈频率：[每天 / 每周]汇总一次给 Agent
- 目标：批准率/准确率从 ___% 到 ___%（如 30% → 70–80%）

失败回退：
- 触发条件：[如 Agent 错误率连续 3 天高于 40% / 接口被封 / 审批人 3 天未审批]
- 回退动作：[如 Agent 只做候选、人工勾选；或切换粘贴文本模式；或暂停接单]
- 兜底：[最坏情况下交付什么：部分结果 + 异常清单，不编数]
- 告知：[谁告知用户，延迟多久]

五、操作清单（照着做）

第 1 步：先当“接活的人”

  1. 写清楚你要卖什么：具体到“谁付钱、为什么付、付多少”；
  2. 不要让 Agent 自己去找买家——买家是你找的，Agent 是干活的；
  3. 写不出“谁付钱、为什么付”，先停，去找需求，不要先上 Agent。

第 2 步：过三道门槛检查

  • 门槛 1：身份——列出所有需要身份的环节（注册、实名、收款、签合同），写清“谁的身份、谁来提供、怎么提供”。身份没人解决，生意跑不通。
  • 门槛 2：真人点头——列出哪些节点必须真人拍板（收款、发布、对外提交、退款等）。每天留 5–15 分钟做审批。不要试图把人彻底拿掉。
  • 门槛 3：交付物——把交付物写成一句话：“用户拿到的是 ___（能跑的脚本 / 能用的页面 / 能省时间的工具），不是 ___（报告）。”写不出来，就说明交付物不对。

第 3 步：卖工具，不卖教程

  • 用户付完钱，能立刻用上什么？
  • 不用你解释，他自己会用吗？
  • 如果答案是“还得看教程”，把教程做进工具里，变成工具的一部分。

第 4 步：用真人反馈带 Agent（像带徒弟）

  1. Agent 只负责调研和写初稿；
  2. 每一单都要真人点批准或拒绝；
  3. 把每一次批准 / 拒绝的原因记下来，反馈给 Agent；
  4. 批准率从 30% 涨到 70–80%，就说明 Agent 越带越准了。

六、提示词（可复制）

提示词 A：检查一个 Agent 赚钱想法靠不靠谱

你在帮我检查一个 Agent 赚钱想法靠不靠谱。

想法：[填入想法]
打算卖什么：[填入产品]

请按三道门槛输出检查结果，不要直接说“能赚钱”：
1. 身份：哪些环节需要身份（注册/实名/收款/签合同）？谁来提供？
2. 真人点头：哪些节点必须真人拍板？每天留多少分钟审批？
3. 交付物：用户拿到的是什么（能用的工具 / 好看的报告）？用一句话写清。

再判断：卖的是工具还是教程？如果是教程，怎么把它做进工具里？

最后给一句话结论：能上 / 不能上 + 缺了哪道门槛。

提示词 B：用真人反馈带 Agent（每周复盘）

你是我的 Agent 学徒带教助手。下面是本周我对你输出的批准/拒绝记录：

批准的：[粘贴 3–5 条 + 批准原因]
拒绝的：[粘贴 3–5 条 + 拒绝原因，如“这条不是待办，是闲聊”“价格抄错了，以截图为准”]

请做三件事：
1. 总结本周被拒绝的共性原因（不超过 3 条）；
2. 针对每条原因，写一句可执行的规则（如“闲聊句不进待办”“价格以截图为准，不编数”）；
3. 输出下周的检查清单（5 条以内），我按它逐条审批。

不要只说“下次注意”，要给出能直接用的规则。

七、常见坑

  • “全自动赚钱 / 挂着就行 / 睡后收入”：先问身份谁解决、节点谁点头、交付物是什么。答不上来，就是割韭菜。
  • “Agent 自己找买家”：Agent 找的是“点子”，不是“买家”。
  • “报告当交付物”：47 个点子、9 份报告，收入 $0。
  • “挤最热闹的街”：生产力工具需求最多，但付费意愿最弱。去找愿意掏钱的那条街（Reddit 9,363 帖分析：金融类需求最少，付费意愿最强）。
  • “抄数字”：$41K、$32K 等为原作者自述、未独立验证。看模式，不要抄数字。
  • “批准了不记原因”：只点批准/拒绝、不记原因，Agent 永远越带越不准。原因记录才是反馈。
  • “教程当工具卖”：用户付完钱还得看教程才用得上，等于卖信息。把教程做进工具里，变成工具的一部分。
