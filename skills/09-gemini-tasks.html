Skill：Gemini 任务模式委托判断（交出去之前，先判能不能交）

前提（付费墙）：任务模式只限 Google AI Pro 与 Ultra 订阅者，免费用户用不了。[S1] 本 Skill 帮你判断“这件事能不能交给任务模式”，不讲 UI 操作、不讲实测、不讲跑分、不讲 API 接入、不讲 Antigravity。

怎么读：带 [S1] / [S2] 的是事实，有来源；没带标记的，是本 Skill 的判断方法。来源表见文末。

手头有一件事，想交给 Gemini 任务模式、让它在你不在电脑前时接着干——交出去之前，花 3 分钟过一遍这个 Skill。目标：判对“交不交、怎么交”，不交错活，不甩锅。

不适合的场景：你已经决定自己做，不需要委托；或者这件事根本没法说清要求——先把要求想清楚，再用这个 Skill。

输入 / 输出 / 验收标准

输入（开始之前，先填清这 5 项，填不清就别交）：

输入项填什么填不清怎么办
任务一句话一句话说清要什么说不清，先想清楚，再交
不要什么明确排除的范围没想好，先写“不要对外发、不要花钱”，再往下判
什么算完交付物长什么样、做到什么程度算完写不出来，说明边界不清，先拆小
对外 / 花钱？会不会对外发出、会不会花钱会，先走“必须人点头”分支
验的方法你回来怎么验、验什么验的方法想不出来，等于没法验收，先补

输出（一份委托简报，见文末提示词 A）：任务一句话 + 不要什么 + 什么算完 + 对外/花钱判定 + 验的方法 + 四问判定结果。缺任何一项，委托简报不合格。

验收标准（回来验的时候，对照这 4 条，全过才算交合格）：

  1. 交付物和“什么算完”一致，不多做、不漏做、不替你发挥。
  2. “不要什么”一条没碰：没对外发、没花钱、没碰敏感信息（除非你事先明确允许）。
  3. 你能用自己定的验的方法快速验完，不用重做一遍才知道对错。
  4. 有问题的地方标出来了，没藏着、没替你做决定。

有一条不过，这次委托判为不合格：不直接用，先按“失败回退”处理，并记一条沉淀（见“审核与知识沉淀”）。

判定方法：四问决策表

四问逐个判，有一问答“否”，就不能直接交。判定结果只有三种：可交 / 拆小再交 / 必须人点头，不存在“先交了再说”。

#问题答“是”才能交答“否”怎么处理
Q1能一句话说清要什么吗？（要什么、不要什么、什么算完）是先把要求想清楚，再交。想不清楚，判为“不能交”
Q2错了能撤回吗？是判为“必须人点头”：先出草稿 / 先给方案，人确认后再往下走
Q3回来能快速验吗？（有明确的验的方法）是先补验的方法。补不出来，判为“不能交”——验不了等于没省时间
Q4它会对外发出 / 花钱吗？否（不会，才可交）判为“必须人点头”：对外 / 花钱动作留给人，任务模式只出草稿 / 选项

决策规则：

  • Q1–Q3 全是“是”，且 Q4 是“否”→ 可交，按委托简报交出去。
  • Q1 或 Q3 答“否”→ 不能交，先补要求 / 补验的方法，补不上就自己做或拆小。
  • Q2 答“否”，或 Q4 答“是”→ 必须人点头，拆成两步：第一步只出草稿 / 选项，第二步人确认后再往下走。绝不一次交到底。

注意：这个决策表是判断方法，不是产品说明。Gemini 任务模式本身会不会在某一步停下问你，以你实际看到的产品提示为准，本 Skill 不编造产品行为。

检查表（判定方法，不是操作教程）

交出去之前，逐项打勾。有一项打不上，就按表中“打不上怎么办”处理，不许跳过。

□检查项怎么判打不上怎么办
☐任务一句话说得清能一句话说清要什么、不要什么、什么算完先想清楚，再交
☐交付物有验收标准回来验什么、怎么验，事先写清补验收标准，补不上不交
☐结果可逆或可改错了能改、能撤回必须人点头：先出草稿，人确认后再往下
☐不直接对外不直接对外发、对外下单、对外提交、对外发布必须人点头：对外动作留给人
☐不直接花钱不直接下单、订座、签约、付款必须人点头：花钱动作留给人
☐不碰敏感信息不含隐私、密码、财务数据、内部未公开信息（除非你事先明确允许并承担后果）默认不交；拿不准就不交

☐失败有回退提前想好：错了 / 没结果 / 结果可疑时怎么处理（见“失败回退”）补回退方案，补不上不交

完整示例 1：可交（整理类，草稿交付）

任务（假设示例，仅演示判定，未实测）：把你已收藏的文章整理成一张清单

委托简报（填好的）：

  • 任务一句话：把已收藏的文章整理成清单草稿。
  • 不要什么：不要删除任何收藏，不要对外发，不要改原文，不要替我下结论。
  • 什么算完：一份清单草稿，每篇一行：标题、一句话摘要、链接。
  • 对外 / 花钱？不会。
  • 验的方法：抽查 3 篇，对照原文看标题、摘要、链接对不对。

四问判定：Q1 是（一句话说得清）；Q2 是（草稿错了能改）；Q3 是（抽查能验）；Q4 否（不对外、不花钱）→ 可交。

验收（回来对照）：清单和“什么算完”一致；没碰“不要什么”；抽查 3 篇全对；可疑摘要标出来了，没藏着。4 条全过，合格。

失败回退（提前想好的）：摘要写错了，不直接用，标出可疑项，人逐条改；清单不全，不默认“就这些”，标出“未覆盖哪些”，人决定要不要补。

完整示例 2：必须人点头（对外发出 + 花钱，拆成两步）

任务（假设示例，仅演示判定，未实测）：把这封道歉信发给客户，并订好今晚的餐厅

四问判定：Q1 是（说得清）；Q2 否（发出去收不回来，订了退起来麻烦）；Q3 是（能验）；Q4 是（对外发 + 花钱）→ 必须人点头，不能一次交到底。

拆法（不是直接放弃）：拆成两步——第一步，任务模式只出“道歉信草稿 + 餐厅选项（3 家，各附价格、时间、可订情况）”，不发、不订；第二步，你看完草稿和选项，亲手发、亲手订。决定权在你手里，才叫委托。

如果没拆，直接交会发生什么：信发错了收不回来，餐厅订错了改起来麻烦——这就是“你不在电脑前，它还在闯祸”。所以 Q2 / Q4 不过的任务，一律拆两步，不许一次交到底。

完整示例 3：不能交（自己都说不清要什么）

任务（假设示例，仅演示判定，未实测）：“帮我把这堆资料出个最终结论发群里”

四问判定：Q1 否（“最终结论”是什么、发给谁看、什么口径，全没说清）；Q4 是（发群里 = 对外发出）→ 不能交。

改法：先把要求想清楚——结论给谁看、用什么口径、哪些能写哪些不能写；再把“发群里”拿掉，改成“先出草稿，我验完再决定发不发”。要求想清楚 + 对外动作拿掉之后，重新过四问，才能判为可交或必须人点头。

冲突 / 超时 / 失败回退

冲突：任务要求和你的边界冲突时，停下来问人，不自行取舍

  • 触发：委托简报里的“不要什么”和任务执行中遇到的情况打架了（比如：你说了“不要对外发”，但任务做完好像“必须发出去才算完”）。
  • 动作：停下，不猜你的意思，不替你做决定；把冲突点写清楚，等你定。
  • 告知：说明“冲突是什么、停在哪一步、需要你定什么”。

超时 / 无结果：不默认“它做完了”

  • 触发：回来发现没结果、结果不全、或者你不确定它做没做完。
  • 动作：不默认成功，不拿半成品当成品用；先确认实际状态，没结果就重新下委托或拆小。
  • 禁止编造：本 Skill 不编造 Gemini 的超时时长、重试次数、报错代码等产品行为，以你实际看到的产品提示为准。

失败 / 结果可疑：不转发、不对外发，退回“人验 + 人定”

  • 触发：验收 4 条有一条不过；或者结果看起来不对，但你一时说不清哪里不对。
  • 动作：标出可疑点，退回人工处理；可疑结果不转发、不对外发、不当作结论用。
  • 恢复条件：问题说清 + 委托简报改好 + 四问重新过一遍，全过才能重新交。改不好，就自己做。

回退模板（复制后填空）

回退记录（任务：___，日期：___）：
触发：___（例：验收第 2 条不过 / 没结果 / 结果可疑 / 冲突）
已停在哪一步：___（例：只出了草稿，未对外发、未花钱）
回退动作：___（例：标出可疑点，转人工处理；对外 / 花钱动作全部留给人）
告知：___（例：已告知 ___，说明“发生了什么、停在哪一步、下一步谁处理”）
恢复条件：___（例：问题说清 + 简报改好 + 四问重过全过，才重新交）

提示词 A：委托简报（交出去之前，先写这份简报）

你按下面这份委托简报干活，不要自行发挥、不要替我做决定。

任务一句话：[填入任务]
不要什么：[填入明确排除的范围，默认写：不要对外发、不要花钱、不要碰敏感信息]
什么算完：[填入交付物长什么样、做到什么程度算完]
对外 / 花钱？[填入：不会 / 会（会的话只出草稿/选项，不发、不订）]
验的方法：[填入：我回来怎么验、验什么]

判定结果：[填入四问结果：可交 / 拆小再交 / 必须人点头]
如果判定是“必须人点头”，第一步只出草稿/选项，不对外发、不花钱，等我确认再往下走。
如果执行中遇到冲突，停下来，把冲突点写清楚，等我定，不要自行取舍。

提示词 B：回来验收（回来之后，对照交付物逐项验）

你是这次委托的验收员。委托简报：[粘贴提示词 A 的完整简报]。
交付物：[粘贴交付物或说明交付物在哪]。

请按验收标准逐项输出，不要只说“完成了”：
1. 交付物和“什么算完”一致吗？（不多做、不漏做、不替我发挥；不一致的逐条列出）
2. “不要什么”碰了没有？（没对外发、没花钱、没碰敏感信息；碰了的逐条列出）
3. 我能用自己定的验的方法快速验完吗？（验的方法是什么、验的结果是什么）
4. 有问题的地方标出来了吗？（可疑点逐条列出，不要藏着）

最后给一句话结论：这次委托合格 / 不合格 + 理由。不合格的，按回退模板写回退记录。

审核与知识沉淀

每次委托，记一条沉淀（30 秒写完，下次少踩一次坑）：

沉淀记录（日期：___）：
任务一句话：___
四问判定：可交 / 拆小再交 / 必须人点头（Q1___ Q2___ Q3___ Q4___）
实际结果：合格 / 不合格（验收哪条过了、哪条没过）
哪里判错了：___（例：Q3 判“能验”，实际验起来比做还费劲）
下次怎么判：___（例：这类活以后 Q3 直接判“否”，先补验的方法）

每周复盘（5 分钟，对着沉淀记录看一遍）：本周交了几次、合格几次、判错集中在哪一问、哪类活以后直接判“必须人点头”或“不能交”。复盘结论写成一条规则，贴进下次的委托简报里。

常见坑（7 条）：

  • “连了 40+ 应用 = 什么都能办”：错。连接 [S1] 不等于替你办事，更不等于对外动作不用你点头。
  • “任务模式 = 不用管了”：错。你不在电脑前 ≠ 你不用负责。回来验结果、做决定，依然是你的活。
  • “API 价格 = 订阅价格”：错。$2 / $10 是开发者博客公布的 API introductory 价格 [S2]，App 任务模式的可用范围是 Pro / Ultra 订阅 [S1]。两篇博客，两笔账。
  • “说不清也先交了再说”：错。Q1 不过，先想清楚，再交。想不清楚，交出去也是白交。
  • “错了撤不回也交”：错。Q2 不过，一律拆两步：先出草稿，人确认后再往下走。
  • “验不了也交”：错。Q3 不过，等于没省时间，只是把活从“做”变成了“查”。
  • “对外 / 花钱一次交到底”：错。Q4 是，一律必须人点头。对外 / 花钱动作留给人，任务模式只出草稿 / 选项。
