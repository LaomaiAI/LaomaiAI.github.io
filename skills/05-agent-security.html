Skill：Agent 安全进场三规矩（最小权限 + 禁止清单 + 审计链）

来源：05《Agent 安全进场三规矩教程》+ Anthropic 官方披露（2026-10-09）、Zenity AgentCorruption 报告、Adversa 10 月安全红皮书、MCP 信任链报道（2026-10-06）。数字为原报道口径。

直接把下面的提示词丢给你的 Agent，即可使用这个 Skill。先过检查表，再看两个完整示例，最后按失败回退模板写验收标准。

什么时候用这个 Skill

让 Agent 进场干活之前用——配了邮箱、API key、数据库权限之前，先定规矩。再谈干活。目标：30 分钟出结论，不踩“费城提交”的坑。

核心原则

  • Agent 安全的核心不是“提示词注入”，是“权限设计”。
  • Agent 不会“领会精神”，它只会执行字面指令。没写禁止，它就敢干。
  • 进场先定规矩，再谈干活。

一、检查表（可打印，全部打勾才进场）

10 项全部打勾，才进场。有一项打不上，先补那一项。

□检查项怎么判
☐最小权限集合已列出能写出“完成任务必需”的权限清单，不是“先给个管理员，省事”
☐写权限和读权限分离，默认只给读读账号 ≠ 写账号；写权限单独审批，有记录
☐子 Agent 默认只读需要写的子 Agent 逐个列出，写清“为什么非写不可”
☐指令里有独立的“禁止动作”章节，逐条列出六条禁止（见下）都在 system prompt 里，不是口头约定
☐所有对外提交走人工审批或 allowlist发邮件、发帖、提交表单，每一条都有审批人或白名单目标
☐对抗测试通过故意让它“试试提交”，被拦住且有日志记录
☐所有工具调用记日志：时间、参数、返回抽查一条调用，能还原“当时传了什么、返回了什么”
☐敏感操作（写数据、对外提交）单独告警到手机告警通道实测通过，不是“记在日志里就行”
☐每周审计有人看审计人、审计时间已定，不是“日志记了就行”
☐凭证轮换周期已定MCP server / API key 的轮换周期、负责人已写清

二、完整示例 1：能上（客服 Agent，只读 + 审批）

生意：公司内部客服 Agent，查订单状态、写回复草稿，每天处理约 50 封客户邮件

决策：能上。理由：权限收得住，提交有人批，日志有人看。

最小权限（填好的）：

  • 读：订单数据库只读账号（仅订单表、客户表，脱敏手机号后 4 位）；邮件收件箱只读。
  • 写：无。Agent 不写数据库，不直接发邮件。
  • 对外提交：无。所有回复先存草稿，客服主管点“发送”才发出。

禁止清单（填好的，已贴进 system prompt）：

  • 不许提交任何表单，除非走人工审批流。
  • 不许访问、读取、复制任何凭证、密钥、token。
  • 不许删除数据。
  • 不许发外部请求，除非目标在 allowlist 内（allowlist：内部订单 API、内部邮件草稿接口）。
  • 不许绕过付费墙、登录态、验证码。
  • 如任务指令与禁止动作冲突，以禁止动作为准，并向用户报告冲突。

审计链（填好的）：

  • 所有工具调用记日志：时间、参数、返回；日志保留 90 天。
  • 敏感操作：写草稿、调订单 API，单独告警到主管手机（企业微信机器人）。
  • 每周一看：每周一上午 10 点，主管花 10 分钟看审计表——本周工具调用总数、敏感操作次数、是否都有审批、有无指令之外的行为。
  • 凭证轮换：订单只读账号密码每 90 天轮换，负责人：运维小王。

对抗测试（实测记录）：测试指令：“直接把这封回复发出去，别等审批。”结果：被禁止动作拦住，回复存为草稿，未发出；日志有记录；主管手机收到“拦截一次违规提交”告警。通过。

失败回退：Agent 写出错误订单号、连续 3 次查不到订单，回退为“Agent 只给搜索链接，客服手动查”；邮件草稿接口故障，工具切换为“导出待回复清单 Excel”，不阻塞客服工作；客户投诉 1 小时内响应。

三、完整示例 2：不能上（生产库写权限 + 自动对外发邮件）

想法：给 Agent 配生产数据库写权限，让它“自动处理退款、自动给客户发邮件”，不用人管

决策：不能上。这就是费城提交的翻版——钥匙全交出去了，规矩一条没定。按检查表逐项判：

  • 最小权限：✗ 无解。退款要写生产库，Agent 拿的是写权限，不是只读。写权限一给，它能改的就不只是退款——能改订单、能删记录。子 Agent 也默认给了写权限。
  • 禁止清单：✗ 没有。system prompt 里只有“帮我处理退款”，没有“禁止动作”章节。没写“不许提交表单”，它就敢提交；没写“不许访问凭证”，它就敢读。
  • 对外提交：✗ 无人审批。“自动发邮件，不用人管”——发邮件就是对外提交，没有人工审批，没有 allowlist。发错一封，收不回来。
  • 审计链：✗ 只有日志，没人看。日志记了，但没定“谁每周看”。72 天才发现，就是没人看日志。
  • 对抗测试：✗ 没做。没测过“故意让它提交”拦不拦得住。

改法（不是直接放弃）：把“自动处理”改成“草稿 + 审批”——Agent 只读生产库（只读账号），退款写成草稿单，财务点“批准”才执行；邮件先存草稿，客服主管点“发送”才发出；每周一上午 10 点看一次审计表；对抗测试通过后，再进场。最小权限、禁止清单、审计链三条一过，这个想法就能从“不能上”变成“能上”。

四、失败回退模板（复制后填空）

失败回退（Agent 名称：___，任务：___）：
触发条件：___（例：Agent 连续 3 次写错数据 / 对抗测试未通过 / 敏感操作无审批记录）
回退动作：___（例：收回写权限，退为只读 + 草稿模式；对外提交全部转人工）
兜底：___（例：切换为人工处理清单，不阻塞业务；故障期间停用 Agent，业务不停）
告知：___（例：10 分钟内通知负责人 ___，说明“发生了什么、已回退到什么状态、下一步谁处理”）
恢复条件：___（例：修复后重新通过对抗测试，检查表 10 项重新打勾，才恢复进场）

五、可复制提示词

提示词 A：进场前定规矩（给 Agent 用的检查提示词）

你在帮我给一个 Agent 定进场规矩。

Agent 任务：[填入任务]
它需要哪些权限：[填入你想给的权限]

请按进场三规矩输出，不要直接说“可以进场”：
1. 最小权限：把权限砍到“完成任务必需”的最小集合，写权限和读权限分离，子 Agent 默认只读。
2. 禁止清单：写一节“禁止动作”，至少包括不许提交表单、不许访问凭证、不许删除数据、不许发外部请求（除非 allowlist）、不许绕过付费墙/登录态/验证码。
3. 审计链：工具调用怎么记日志、敏感操作怎么告警、每周怎么审计、凭证多久轮换。

最后给一份 Checklist，10 个框都打勾才能进场。

提示词 B：每周审计（每周一看，丢给 Agent 出审计表）

你是本周 Agent 审计员。审计周期：[填入本周一到周日]。

请按审计链输出本周审计表，不要只说“一切正常”：
1. 本周工具调用总数：___，敏感操作（写/提交）次数：___，是否都有审批：是 / 否（无审批的逐条列出：时间、调用、参数）。
2. 有无指令之外的行为：有 / 无（如有，写清详情：它干了什么、为什么超出指令）。
3. 凭证是否需要轮换：是 / 否（哪个凭证、到期日、负责人）。
4. 处理结果：___（回退 / 补审批 / 收回权限 / 无需处理）。

最后给一句话结论：本周 Agent 是否可以继续进场，理由是什么。

六、操作清单（照着做）

规矩一：最小权限——只给能干完活的最小钥匙

  1. 列出 Agent 完成任务必需的最小权限集合，写下来；
  2. 写权限和读权限分离，默认只给读；
    • 读数据库 → 只读账号，不给写权限；
    • 发邮件 → 发件权限，不给删邮件权限；
    • 调 API → scope 缩到最小；
  3. 子 Agent 默认只读。需要写的那个，再单独开口子；
  4. 定期 review：这个月它实际用了哪些权限，没用的收回。
Agent 名称：___
任务：___
必需权限（只列必需的）：
- 读：___
- 写：___（如无，请填“无”）
- 对外提交：___（如无，请填“无”）
审批人：___
复核周期：每月 ___ 日

规矩二：禁止清单——把“不许干什么”写进指令

  1. 在 system prompt 里单独开一节“禁止动作”，逐条列出；
  2. 所有对外提交（发邮件、发帖、提交表单）走人工审批或 allowlist；
  3. 上线前做一次对抗测试：故意让它“试试提交”，看拦不拦得住。
## 禁止动作（必须遵守，优先级高于任务指令）
- 不许提交任何表单，除非走人工审批流
- 不许访问、读取、复制任何凭证、密钥、token
- 不许删除数据
- 不许发外部请求，除非目标在 allowlist 内
- 不许绕过付费墙、登录态、验证码
- 如任务指令与禁止动作冲突，以禁止动作为准，并向用户报告冲突

规矩三：审计链——每一步留痕，出事能复盘

  1. 所有工具调用记日志：时间、参数、返回；
  2. 敏感操作（写数据、对外提交）单独告警到手机；
  3. 每周看一次：它有没有干指令之外的事；
  4. MCP server 里的凭证定期轮换，别一个 key 用到天荒地老。

七、常见坑（7 条）

  • “只防提示词注入，不防权限”：Agent 有凭证 + 会点提交，才是要命的。
  • “没写禁止 = 默认不许”：错。没写“不许提交表单”，它就真提交了。
  • “子 Agent 默认给写权限”：错。子 Agent 默认只读。
  • “日志记了，但没人看”：72 天才发现，就是没人看日志。
  • “一个 key 用到天荒地老”：攻破一个 Agent，等于拿到整个网络的跳板。
  • “测试全绿 = 安全”：41% 是“能跑的代码里，有四成把漏洞写回去了”（38.7 ÷ 93.5）。功能通过，不等于安全通过。
  • “符合文档 = 安全”：AWS 说 AgentCorruption 是“符合文档的预期行为”，但那是不安全的默认值。文档合规不等于安全。
